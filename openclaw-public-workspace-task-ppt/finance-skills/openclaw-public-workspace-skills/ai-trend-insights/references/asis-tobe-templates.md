## 场景库

### 场景 A：信贷审批流程

**[AS-IS]**
- 客户提交申请 → 人工收集材料（1-3天）→ 信审专员审核（2-5天）→ 多级审批（3-7天）
- 耗时：7-15天
- 成本：每笔¥800-1500人工成本
- 局限：依赖专员经验，审核标准不一致；晚上/节假日无法处理

**[TO-BE]**
- 客户语音/文字描述需求 → AI Agent自动收集并核验材料（<30分钟）→ AI完成初审并给出评分及理由 → 仅超阈值案例人工复核
- 耗时：<2小时（标准件）
- 成本：每笔¥50-150（节省80%）
- 实现前提：私有大模型部署 + 征信数据API接入 + 合规红线设定

---

### 场景 B：合规审查

**[AS-IS]**
- 合规人员逐条阅读合同（单份100-300页）→ 人工比对监管规定 → 出具意见（3-10天）
- 上下文限制：人工每次只能关注局部，易遗漏跨页关联条款
- 年均合规成本：大行¥5-20亿

**[TO-BE]**
- 完整合同一次性输入长上下文模型（支持百万tokens）→ AI识别所有潜在合规风险点并标注位置和理由 → 人工只需审核AI标注的高风险条款
- 耗时：<30分钟/份
- 关键技术：长上下文模型（需≥200K tokens）+ 法规知识库RAG
- 备注：此场景是长上下文突破的最直接金融应用

---

### 场景 C：客户经理工作模式

**[AS-IS]**
- 客户经理手动查阅客户历史 → 准备会前材料（2-3小时）→ 依靠个人记忆跟进 → 离职导致客户关系断层

**[TO-BE]**
- AI助手实时汇总客户全貌（含历史交互、持仓、生命周期事件）→ 会前5分钟自动生成个性化简报 → 自动记录跟进事项 → 客户关系存于机构而非个人
- 关键技术：长上下文（跨会话记忆）+ 客户数据平台集成
- 预期价值：客户经理服务容量提升3-5倍

---

### 场景 D：AI开发模式

**[AS-IS]**
- 业务提需求 → IT理解需求（常有偏差）→ 外包开发（3-6个月）→ 上线测试（1-2个月）→ 不断修改
- 典型IT项目周期：6-18个月
- 业务参与度：低（只能看最终结果）

**[TO-BE]（Cowork/SKILL范式）**
- 业务专家用自然语言描述规则 → 平台自动生成SKILL/工具 → 业务自测自改 → 1-5天上线
- 典型AI应用周期：1-2周
- 业务参与度：全程主导
- 实现前提：低代码AI平台 + 业务人员培训 + IT提供数据接口

---

### 场景 E：互联网金融入口竞争

**[AS-IS]**
- 用户需求产生 → 打开银行App → 导航找功能 → 填写表单 → 等待处理
- 银行App是金融服务的核心入口
- 竞争维度：功能完整性、界面易用性

**[TO-BE]**
- 用户对AI（微信/支付宝/手机助手）说"帮我理财" → AI调用银行API完成 → 用户无需打开银行App
- 竞争威胁：银行App可能被"管道化"（变成后台API提供者）
- 竞争维度转变：从"App体验"→"API能力+AI可调用性"
- 战略含义：银行需要同时建设面向用户的AI和面向AI的开放API

---

### 场景 F：投研报告生成

**[AS-IS]**
- 分析师收集数据（1-2天）→ 阅读研报/财报（2-3天）→ 撰写报告（1-2天）→ 审核发布（1天）
- 总耗时：5-8天/份
- 质量依赖：分析师个人能力和信息获取渠道

**[TO-BE]**
- AI Agent自动收集数据（实时）→ 一次性处理所有相关文档（长上下文）→ 生成结构化初稿（<1小时）→ 分析师补充判断和观点 → 发布
- 总耗时：<1天
- 分析师角色转变：从"数据处理者"→"判断力提供者"
- 关键技术：长上下文 + Web搜索工具 + 金融数据API

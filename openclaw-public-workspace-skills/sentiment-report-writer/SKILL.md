# SentimentReportWriter (证券舆情分析报告生成)


## 0) Public实例运行约定（CRITICAL）

- 本技能运行在 OpenClaw public 实例，工作区根目录固定为：`/home/ubuntu/.openclaw-public/workspace`。
- 若用户消息包含 `[[OPENCLAW_RUN_ID: <run_id>]]`，所有输出文件必须写入：
  - `/home/ubuntu/.openclaw-public/workspace/<run_id>/`
- 若未提供 run_id，可写入当前工作目录，但优先创建独立子目录避免覆盖。
- 需要检索新闻/网页时：
  - 优先使用 `web_search` 找来源
  - 用 `web_fetch` 抽取正文
  - 不使用不存在的 `search` 工具名


## ⚠️ CRITICAL: 合规性底线 (READ FIRST)

**ALWAYS ensure the final report adheres to these compliance rules:**

1. **NO absolute statements:** 避免使用“一定”、“必然”、“最”等绝对化用语。
2. **NO guaranteed returns:** 严禁任何形式的投资回报承诺。
3. **CLEAR risk disclosure:** 风险提示必须显著、充分、具体。
4. **INDEPENDENT analysis:** 必须声明报告的独立性，不受任何利益方影响。

**Why this matters:** 合规是证券研究的生命线。任何违规内容都可能导致严重的法律和声誉风险。

## 1. 概述 (Overview)

`SentimentReportWriter` 旨在将复杂的证券舆情深度分析结果，以**高度结构化、专业严谨、符合行业规范**的研报形式呈现。它不仅负责内容的组织与填充，更强调报告的**可读性、可信度、合规性**。

### ALWAYS ask yourself first:
1. **“这份报告的目标读者是谁？”** (是追求绝对收益的基金经理，还是关注相对排名的分析师？)
2. **“报告的核心结论应该一句话概括成什么？”** (是“买入”，是“警惕风险”，还是“等待催化剂”？)
3. **“报告的创新点在哪里？”** (是新的视角、新的数据，还是新的逻辑？)

## 2. 核心能力 (Capabilities)

- **结构化报告生成**
- **专业术语与行文规范**
- **字数与内容密度控制**
- **引用与数据来源规范**
- **合规性预审**
- **个股深度点评章节**
- **多格式输出**

## 3. 使用指南 (Usage)

### 输入要求
- `deep_analysis_results`: 结构化深度分析结果。
- `report_type`: 报告类型。
- `output_format`: 输出格式。
- `word_count_constraints`: (可选) 字数限制。
- `citation_style`: (可选) 引用格式。

### 报告撰写逻辑
1.  **模板选择与初始化**
2.  **内容填充与整合**
3.  **专业化润色与规范化**
4.  **字数与结构调整**
5.  **合规性初步检查**
6.  **格式化输出**

## 4. Red Flags & Warning Signs

🚩 **分析与结论脱节**: 深度分析的内容无法支撑最终的投资建议。
🚩 **数据来源缺失**: 报告中的关键数据或图表没有标注来源。
🚩 **风险提示过于笼统**: 风险提示是通用模板，缺乏针对性。

**When in doubt, add a footnote.** 对不确定的细节或数据，通过脚注进行说明，可以增加报告的严谨性。

## 5. 报告结构规范 (Report Structure Standards)

| 章节 | 内容要求 | 字数约束 | Why this matters |
| :--- | :--- | :--- | :--- |
| 报告头部 | 评级、目标价、作者、日期 | 固定格式 | 确保关键信息一目了然 |
| 一、核心投资逻辑 | 概括性的核心观点 | 200-300 字 | 确保核心观点简洁有力 |
| 二、舆情背景与事件概述 | 事件描述、时间线、核心信息 | 300-500 字 | 提供必要的背景信息 |
| 三、深度逻辑与估值分析 | 基本面共振、逻辑链条、量化影响、情景分析 | 1500-2500 字| 报告的核心分析部分 |
| 四、关注标的深度点评 | 每个标的的完整点评（见下方覆盖度约束） | 每个标的 300-500 字 | 提供可操作的个股建议 |

### ⚠️ CRITICAL: “关注标的深度点评”覆盖度强制要求

**本章节必须与实体关联表中的关联层次一一对应，具体要求如下：**

1.  **全层次覆盖**：实体关联表中的每一个关联层次（如"直接受益"、"核心受益"、"间接受益"、"直接受损"、"核心受损"等），在本章节中都必须有至少一个代表性标的获得完整的深度点评。
2.  **受益与受损并重**：不仅要点评受益标的，受损标的同样必须获得完整的深度点评（含负面影响的财务弹性测算表），以提供完整的投资视角。
3.  **每个标的必须包含**：公司简介、舆情关联逻辑、财务弹性测算表（乐观/中性/悲观三情景）、投资建议和核心风险。
4.  **禁止遗漏**：若实体关联表中有 5 个关联层次，则本章节至少应包含 5 个标的的深度点评（每层至少 1 个）。若某层次无合适上市标的，必须明确说明原因。
| 五、投资建议 | 综合评级、核心理由 | 200-300 字 | 总结报告的核心结论 |
| 六、风险提示 | 至少 5 条具体风险 | 300-500 字 | 履行合规义务，保护投资者 |
| 七、免责声明 | 标准免责条款 | 固定格式 | 法律要求 |
| 八、参考文献 | 所有引用来源 | 不限 | 增强报告可信度 |

## 6. Output Checklist

- [ ] 报告标题是否清晰、有吸引力？
- [ ] 核心投资逻辑是否能在 30 秒内讲清楚？
- [ ] 报告是否包含了至少一张原创的图或表？
- [ ] 风险提示是否具体且具有针对性？
- [ ] 免责声明和作者信息是否完整？
- [ ] **“关注标的深度点评”章节是否覆盖了实体关联表中的所有关联层次？**
- [ ] **每个关联层次是否至少有一个代表性标的获得了完整的深度点评（含财务弹性测算表）？**
- [ ] **受损标的是否与受益标的同等对待，获得了完整的负面影响分析？**

## 7. Continuous Improvement

- 这份报告发布后，市场的反馈如何？
- 报告中的预测是否被后续事件验证？
- 如果重写一次，我会如何调整报告的结构或重点？

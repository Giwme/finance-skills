# PPT布局模式参考（用户风格手册）

本文件描述用户偏好的PPT布局模式，**每次生成PPT时必须参照此文件**，确保输出风格一致。

---

## 核心设计哲学

用户的PPT风格具有以下显著特征（来自实际样张分析）：

1. **强结构性**：每页内容按2-3列严格分区，不使用自由排列
2. **灰色卡片框**：每个内容区域用浅灰圆角矩形包裹，形成清晰边界
3. **红色强调**：标题、关键数字、结论用华为红（`#C00000`）
4. **底部结论条**：页面底部横跨全宽，用灯泡图标引导，加粗结论
5. **内嵌图表**：有趋势数据时，必须在卡片内画折线图/曲线图（不可省略）
6. **高信息密度**：每页容纳3-5个要点，内容精练但完整

## 布局类型A：三列横向分栏（最常用）

**适用场景：** 展示三个并列维度/趋势（如模型能力演进三方向）

```
╔══════════════════════════════════════════════════════════════╗
║  页面主标题（红色加粗，左对齐）              [右上角章节tag] ║
╠══════════════════╦══════════════════╦══════════════════════╣
║ ┌──────────────┐ ║ ┌──────────────┐ ║ ┌──────────────────┐ ║
║ │【红色小标题】 │ ║ │【红色小标题】 │ ║ │【红色小标题】   │ ║
║ │              │ ║ │              │ ║ │                  │ ║
║ │ [折线图]     │ ║ │ [循环图/流程] │ ║ │ [层级架构图]    │ ║
║ │              │ ║ │              │ ║ │                  │ ║
║ │ • 要点一     │ ║ │ • 要点一     │ ║ │ • 要点一        │ ║
║ │ • 要点二     │ ║ │ • 要点二     │ ║ │ • 要点二        │ ║
║ │ • 要点三     │ ║ │ • 要点三     │ ║ │ • 要点三        │ ║
║ └──────────────┘ ║ └──────────────┘ ║ └──────────────────┘ ║
╠══════════════════╩══════════════════╩══════════════════════╣
║ 💡 金融影响：[核心结论加粗] — [具体建议]                    ║
╚══════════════════════════════════════════════════════════════╝
```

**pptx-nodejs 实现关键点：**
- 三列 x 坐标：0.3", 3.5", 6.7"；每列宽度：2.9"
- 灰色矩形：`fill: {color: 'F4F4F4'}`，`line: {color: 'E0E0E0', width: 0.5}`
- 底部结论条：y 从 6.5"，高 0.9"，背景 `#FFF8E7`

## 布局类型C：三行KPI框架

**适用场景：** 展示收入/风险/效率三维度价值体系

```
╔══════════════════════════════════════════════════════════════╗
║  指标体系：基于[X]、[Y]、[Z]三大要素构筑AI价值体系 [tag]    ║
║  副标题：从不同价值维度，凸显大模型要素+平台能力的价值贡献   ║
╠══════════════════════════════════════════════╦═══════════════╣
║ ┌──────────────────────────────────────────┐ ║   价值倍增    ║
║ │ 1. 促收入 = AI触客率 × 产品收益 × 转化率 │ ║  ────────── ║
║ │  ▶ [一句话说明智能营销场景]              │ ║  ↑ 用户规模  ║
║ └──────────────────────────────────────────┘ ║  ↑ 活跃度   ║
║ ┌──────────────────────────────────────────┐ ║  ↑ 产品丰富  ║
║ │ 2. 控风险 = AI召回率 × 反欺诈 × 准确率   │ ║  ↓ 风险损失  ║
║ │  ▶ [一句话说明风控反欺诈场景]            │ ║  ↓ 合规成本  ║
║ └──────────────────────────────────────────┘ ║  ↓ 人力成本  ║
║ ┌──────────────────────────────────────────┐ ║  ......      ║
║ │ 3. 提效率 = AI数字劳动力 × 自动化 × 复杂度│ ║              ║
║ │  ▶ [一句话说明智能审核场景]              │ ║              ║
║ └──────────────────────────────────────────┘ ║              ║
╠══════════════════════════════════════════════╩═══════════════╣
║  [底部大模型能力演进路径] + [平台能力演进路径]（双框）       ║
╚══════════════════════════════════════════════════════════════╝
```

**注意：** 三个KPI框中的变量名（如"AI触客率"、"产品收益"）用红色加粗显示。

## 折线图生成规范（当内容有趋势数据时必须生成）

判断条件：内容中出现以下任一情况，**必须**在对应卡片内嵌折线图：
- 上下文长度/参数规模随时间变化
- 模型数量/能力指标增长趋势
- 市场份额/渗透率变化

**代码模板（pptx-nodejs）：**
```javascript
// 折线图配置
slide.addChart(pptx.ChartType.line, chartData, {
  x: cardX + 0.1, y: cardY + 0.8,
  w: cardWidth - 0.2, h: 1.6,
  chartColors: ['C00000', '919191', '1D1D1A'],
  lineDataSymbol: 'none',
  lineSmooth: true,
  showLegend: true,
  legendPos: 'r',
  legendFontSize: 7,
  dataBorder: { pt: 2 },
  valAxisLabelFontSize: 8,
  catAxisLabelFontSize: 8,
  showValue: false,
  // 在末端数据点标注最新值
  dataLabelPosition: 'r',
  showLabel: true,
  dataLabelFontSize: 7,
  dataLabelColor: 'C00000'
});
```

## 右上角章节Tag规范

每页右上角需有面包屑导航（小红色底白字）：
```
[当前章节名] > [子章节名]
例：AI趋势洞察及 > 算力基础设施及
    同业实践        创建设
```
用红色圆角矩形 + 白色文字，字号 9pt。

## 底部结论栏文案规范

结论必须是**金融业务视角**，而非技术视角：

❌ 错误："模型上下文窗口扩大到100K tokens"
✅ 正确："AI能力端到端地持有一个完整的业务上下文——研究、风控、合规、运营中那些长期依赖人工在多份文档、多套系统间反复拉取、比对、串联的知识密集型流程，正在被重构为可编排、可审计、可规模化的自动化工作流"

结论长度：1-2句话，总计40-80字。
